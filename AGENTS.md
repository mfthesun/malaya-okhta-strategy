# AGENTS.md

Инструкция для ИИ-агентов и участников команды.

Командный проект ИТМО: **стратегия развития района Малая Охта (Красногвардейский район Санкт-Петербурга) на 2027–2035** — итоговое задание дисциплины «Формирование пространственного видения города». Язык проекта, документации и коммитов — русский.

## Что это за проект

Конечные продукты:
1. `docs/strategy.md` — стратегия развития Малой Охты 2027–2035: проблемы, миссия, видение, цели и задачи с индикаторами, пространственная модель, мероприятия с хронологической привязкой и увязкой с мировыми кейсами (`docs/world_cases.md`), флагманские проекты, риски.
2. `presentations/` — презентация к защите: контент слайдов для Figma (`presentations/slides.md`) + черновой pptx в дизайн-системе курсов.

Пайплайн: данные (`data/raw`) → обработка (`scripts/process.py`, `data/processed`) → анализ и карты (`notebooks/`) → документы (`docs/`) → презентация (`presentations/`). Все числа в документах воспроизводимы ноутбуками и проверяются `scripts/check_numbers.py` (по образцу altai-spatial-planning).

Методика наследует отработанные проекты команды: структура «Диагностика → SWOT → Доктрина → Модель → Мероприятия → Флагманы» (`~/Projects/altai-spatial-planning/docs/doctrine_draft.md`), приём «несколько версий границ» и дисциплина воспроизводимости (`~/Projects/kolomna-identity/AGENTS.md`), пайплайн и валидация слоёв (`~/Projects/primorsk/AGENTS.md`).

## Правила работы с данными

- **CRS**: геометрии хранятся в EPSG:4326 (GeoJSON); метрические расчёты, площади и карты — EPSG:32636 (UTM 36N, как в kolomna-identity; СПб ближе к центральному меридиану 33° в. д., чем к 27°).
- **CSV с кириллицей** — `utf-8-sig`.
- `data/raw/` не редактировать; все преобразования — в `scripts/process.py` с результатом в `data/processed/`. После изменений: `python3 scripts/process.py && python3 scripts/validate.py` → 0 ошибок.
- Новые исходные данные — в `data/raw/` + запись в `docs/data_catalog.md` (источник, дата, лицензия, оговорки).
- Число в документе, которое можно пересчитать из данных репозитория, обязано проверяться `scripts/check_numbers.py` (строка в `CHECKS`). Внешние числа (веб, документы вне репозитория) — в `docs/numbers_check.md` с пометкой `[проверить]`, в слайды только после сверки с первоисточником.
- Каждая версия границ района — отдельное поле (`v1`, `v2`, `v3`, `v4`) в датасетах, по образцу Коломны. Не путать версии: v1 — историческое ядро, v2 — МО Малая Охта (официальная территория), v3 — охтинский полуостров, v4 — расширенная.

## Оговорки по данным

- Население: ряд по МО Малая Охта есть в `data/raw/population_spb_mo_2010_2025.csv` (ВПН-2010, оценки Петростата, ВПН-2020); скачок 2022→2023 — пересчёт по итогам ВПН-2020, не «чинить».
- Возрастно-половой состав существует только по Красногвардейскому району, не по МО — всегда оговаривать в слайдах.
- Часть записей ЕГРОКН по СПб без координат — привязка по адресам с указанием способа в колонке.
- OSM-счётчики «плывут» от прогона к прогону: цифры в документах фиксируются по конкретному прогону (дата в `docs/data_catalog.md`), повторный экспорт без задачи не нужен.

## Карты

- Единый макет — `scripts/maptools.py` (адаптация altai-spatial-planning): подложки Esri без подписей, атрибуция, указатель севера со сближением меридианов, линейка, легенда справа. Заголовков на карте нет — заголовок пишет слайд.
- В надписях — «е» вместо «ё», неразрывные пробелы после однобуквенных слов и чисел (это делает maptools).

## Стиль

- Комментарии, имена колонок, выводы ноутбуков — по-русски.
- В текстах и слайдах — «е» вместо «ё» (конвенция презентаций команды).
- Слайд-формат: рисунок + подпись + заголовок + тезис + источники + «что не перепроверено» (образец: `~/Projects/altai-spatial-planning/docs/slides_01-03.md`).

## Чего не делать

- Не коммитить файлы больше ~10 МБ без явного согласования (HOITH gpkg, сырые выгрузки).
- Не переписывать историю git и не делать force push: репозиторий учебный, ссылку получают соавторы.
- Не переводить интерфейс и документы на английский.
- Не менять верстку карт вне maptools.py: все карты одного размера и одинаковой компоновки.
